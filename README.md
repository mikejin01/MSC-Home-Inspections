# MSC Home Inspections LLC — Website

A one-page marketing site for **MSC Home Inspections LLC**, a home inspection business
serving the New Jersey area. Built with **SvelteKit (Svelte 5)** as a fully static site,
deployable to GitHub Pages.

The design is a **bento layout** — rounded tiles of varying sizes on a light field —
with all art direction taken from the client's business flyer
(`docs/Business Flyer.jpg`). See [`docs/website-brief.md`](docs/website-brief.md)
for the full brand brief and [`docs/asset-manifest.md`](docs/asset-manifest.md) for
where every image came from.

Scaffolded from the [Hamilton Auto Solution](https://github.com/mikejin01/Hamilton-Auto-Solution)
template. The template's other three themes (editorial, minimalist, illustrative), the
style switcher, and all of its demo media were removed — this repo carries the bento
theme only.

## Run locally

Uses [pnpm](https://pnpm.io) (`corepack enable` if you don't have it):

```bash
pnpm install
pnpm dev           # dev server at http://localhost:5173
```

Build / preview the production static site:

```bash
pnpm build         # outputs static files to ./build
pnpm preview       # serve the built site locally
```

`src/lib/content.js` is the single source of truth for copy — nearly every text change
should happen there, not in the component.

> **On a live WordPress site, the database wins over `content.js`.** Client edits made
> on the live site shadow these defaults, so run `make check-content-drift` before
> changing copy here. See [Content sync](#content-sync).

## The contact form

Where a submission goes depends on where the site is running:

| Host | Destination |
| --- | --- |
| WordPress | `POST /wp-json/xo/v1/lead` → saved under **Leads**, emailed to the address in X.O. Admin |
| Static, `FORM_ENDPOINT` set | that endpoint ([Formspree](https://formspree.io), [Basin](https://usebasin.com), …) |
| Static, nothing configured | opens the visitor's mail client, pre-filled |

Each option falls through to the next on failure, so a visitor who has just typed out
their details is never left with nothing. The form carries a honeypot field that bots
fill and people never see.

## Deploying

### GitHub Pages

`.github/workflows/deploy.yml` builds and publishes on every push to `main`. It sets
`BASE_PATH` automatically so the site works from a project page
(`https://<user>.github.io/<repo>/`). For a custom domain, add a `CNAME` file to
`static/` and leave `BASE_PATH` unset so the site serves from `/`.

### WordPress on SiteGround

The same source also builds into a WordPress theme, which is what turns the site into
something the client can run themselves — business details on an **X.O. Admin** screen,
inspection requests on a **Leads** page, and inline editing of text, images and links on
the live site.

```bash
make build-and-push     # build the theme, rsync it to SiteGround, purge caches
make ssh                # shell on the live server (WP-CLI is preinstalled)
```

Full setup and operations: **[`docs/WORDPRESS-DEPLOY.md`](docs/WORDPRESS-DEPLOY.md)**.
The architecture it implements:
[`docs/SPA-TO-WORDPRESS-THEME-PLAYBOOK.md`](docs/SPA-TO-WORDPRESS-THEME-PLAYBOOK.md).

Everything under `wordpress-theme/` is generated by
[`scripts/build-wordpress-theme.mjs`](scripts/build-wordpress-theme.mjs) and overwritten
on every build — edit the generator, never its output.

### Content sync

Client edits on the live site live in the WordPress database and shadow
`src/lib/content.js`, so the local copy can drift silently out of date:

```bash
make check-content-drift   # exits 1 if the live site has copy this repo lacks
make pull-content          # merge it into src/lib/content-overrides.json, then commit
```

`src/lib/content-overrides.json` is tracked and feeds both builds, so a synced repo and
the live site say the same thing.

## Before this goes live

Content decisions are deliberately conservative: home inspection is a licensed,
liability-sensitive trade, so the site claims **no** credential, price, turnaround time,
rating, or review that the flyer didn't establish. Search `src/lib/content.js` for
`TODO:` — each one marks something the business needs to confirm. The most important:

1. **The NJ home inspector licence number**, plus any InterNACHI / ASHI affiliation.
   Both belong in the footer and the About section; they're the strongest trust signals
   this business has and the site currently shows neither.
2. **A branded email address.** `francocaruso19@icloud.com` is a personal iCloud
   address and currently appears in three places on the page.
3. **Specific counties and towns served** — replacing the generic "New Jersey area" is
   the single biggest local-SEO improvement available here.
4. **Report turnaround time** and whether clients may attend the inspection — both are
   referenced in the How It Works and FAQ sections with placeholder wording.
5. **Real reviews.** There is no testimonials section, because inventing testimonials
   for a real business isn't an option. Once Google reviews exist, that section is worth
   adding — it's the most common conversion driver for this trade.
6. **The original vector logo and high-resolution photography.** Every image on the site
   is currently extracted from the flyer JPEG. See `docs/asset-manifest.md`.
